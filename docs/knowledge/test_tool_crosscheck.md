## 2. Contradictions (bai assumes X, the test tool shows Y)

1. **Reversal pointer direction (high).** bai assumes `DFKKKO-STBEL` on the payment (original) document holds its
   reversal document (`zcl_cd_hck_docchg_dao.clas.abap:31-44`, `zcl_cd_ops_pay_outcome_dao.clas.abap:312-321`,
   `zcl_cd_ops_trace_engine.clas.abap:709-712`, `mapping.json:276`, `links/packages/fica.json:11`). The test tool shows
   on A4H that `STBEL` is filled on the **reversal** and names the reversed document; the original's pointer is
   `STORB` (FINDINGS.md:21, QF-020). As written, the reversal reads return nothing for real reversals. (Some bai
   documents already describe the correct direction: `Performance_Review.md:180, 289`.)
2. **Domain texts through `DDCDS_CUSTOMER_DOMAIN_VALUE_T` (high).** bai expects texts for classic domains (V27,
   param-framework A15, eleven views). On A4H the function returns only ABAP Cloud package domains
   (CHANGELOG.md:18).
3. **Inline declaration in IMPORTING of a functional call (high).** bai's code (five places, one in production code
   `zcl_cd_hck_c_inflight.clas.abap:901`) relies on what abaplint accepts; the 2025 compiler refuses it
   (FINDINGS.md:8, QF-006).
4. **GET PERMISSIONS result value (medium).** bai's tests expect `auth-unauthorized` (01); on A4H a refusal came back
   as 02 (FINDINGS.md:16, QF-015) - to be confirmed for `ONLY GLOBAL AUTHORIZATION`.
5. **NOC lot table (low, both unproven).** bai: NOC items in `DFKKNRP`; test tool: NOC posted as a returns lot with the
   change code in `DFKKRP-RLGRD` (VERIFY C33).
6. **`DPAYH` rows without payment document (low).** bai's `FICA_PAYRUN_NOPAY` treats a blank `DOC1R` of a past run
   as an error; SAP documentation (payment orders) and proposal rows give blank `DOC1R` by design (ROADMAP 13.4).
7. **Test tool against bai (bai is right, do not import):** the test tool assumes reconciliation totals in `DFKKSUMC`
   (`RECON_SUMC_FIELDS`); bai's A4H export shows they are in `DFKKSUM`. The test tool also types `DOC1R` as CHAR 12;
   A4H has `DPAYH-DOC1R` / `DFKKCR-DOC1R` CHAR 24 (bai's export) - no impact on bai's links (`AUGBL` CHAR 12 compares
   fine) but any shared reader must use the dictionary type.

## 3. What bears on the running builds

**K - payment file to bank acknowledgement lifecycle.** Confirmed facts are few: run naming by the scheduler (F18,
X09); the send step is one OS-command wrapper whose variant decides encrypt or send (U04, X19); Control-M / PRISM /
IRIS are the customer's names (U02). Everything else in the test tool on files and ACKs is synthetic (ACK CSV,
PRISM JSON, pain.002 simulator - X20) and must not become the adapter contract. Payment orders post no payment
document until the bank-confirmed order lot (F35) - relevant for the "posting / settlement" stage of the lifecycle.
